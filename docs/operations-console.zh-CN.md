## 一、功能入口与权限

| 功能 | 入口 | 权限 |
| --- | --- | --- |
| 运营数据 | 头像菜单 -> 运营数据，或 `/admin/analytics` | 管理员、超级管理员 |
| 公告管理 | 头像菜单 -> 公告管理，或 `/admin/announcements` | 管理员、超级管理员 |
| 站点公告 | 头像菜单 -> 站点公告，或 `/announcements` | 游客和登录用户，结果按投放范围过滤 |

运营数据和公告管理沿用用户管理权限边界。普通管理员可以使用这两个运营入口，但服务器、安全、备份和其他仅超级管理员可见的配置不会因此开放。

## 二、运营聚合

运营页面只读取 `daily_operation_metrics` 和 `daily_operation_rankings`，不会在每次页面请求时扫描全部业务表。

- API 启动十秒后刷新当天和前一天，此后每小时刷新一次最近两个中国时区自然日。
- 管理员可以手动补算最近 7、30 或 90 天，同一时刻只允许一个聚合任务运行。
- 每次任务写入 `operation_job_runs`，记录运行状态、开始时间、完成时间和错误信息。
- 单日指标按日期唯一写入，可以安全重复补算；单日排行榜在同一事务中替换。
- Redis 不可用时不影响聚合数据写入和页面读取。

| 评论 | 当天新建的文章评论和回复数量 |
| 聊天消息 | 当天发送的私聊、群聊和通知会话消息数量 |
| 文章阅读 | 当天产生的文章阅读记录数量 |
| 点赞 | 当天新增的文章点赞记录数量 |
| 收藏 | 当天新增的文章收藏记录数量 |
| 订阅增长 | 当天新增的作者订阅关系数量 |

## 三、公告生命周期

公告支持以下状态：

- `草稿`：仅后台可见，可以继续编辑或删除。
- `定时发布`：到达发布时间后由每 30 秒运行的生命周期任务发布。
- `已发布`：按投放范围公开，生成站内通知，并可选择浏览器推送。
- `已下线`：到达自动下线时间后停止展示，不允许继续编辑。
- `已归档`：后台保留，普通用户不可见，可以重新发布或删除。

公告可以设置置顶及置顶顺序。定时发布时间必须晚于当前时间，自动下线时间必须晚于发布时间。已发布公告需要先归档才能删除。

## 四、投放、阅读与推送

| 投放范围 | 可见用户 |
| --- | --- |
| 所有访客 | 游客和登录用户 |
| 登录用户 | 任意有效登录账号 |
| 指定角色 | 当前角色命中所选角色的登录账号 |

- 公告列表按置顶、置顶顺序、发布时间倒序展示。
- 登录用户首次打开公告会建立阅读记录，再次打开累加该用户阅读次数。
- 点击“确认已读”后写入确认时间，并同步清除对应站内通知的未读状态。
- 公告管理显示总阅读量、通知接收人数和确认人数。
- 发布公告会通过现有系统通知频道触达目标账号；关闭浏览器推送只关闭系统级推送，不影响站内消息。
- 投放过程使用公告与用户唯一键去重，后台任务重试不会重复生成通知。

## 五、待处理事项提醒

好友申请、群聊邀请、入群申请和群消息举报仍未处理时：

- 当前存在未读提醒时不重复发送。
- 提醒已读后，如果事项继续未处理满 24 小时，系统重新发送一条提醒。
- 数据库使用每日分桶的 `dedupe_key` 唯一键，避免并发任务重复写入。
- 顶部消息角标只统计真正未读的消息和通知；仅有待处理但已读的事项不会显示未读数字。
- 顶部消息气泡保留同意、拒绝、处理和驳回快捷操作。

## 六、主要 API

| 路径 | 作用 |
| --- | --- |
| `GET /analytics/admin?range=7|30|90` | 读取运营聚合、趋势、榜单和统计口径 |
| `POST /analytics/admin/rebuild` | 手动补算 7、30 或 90 天 |
| `GET /announcements/public` | 游客可见公告列表 |
| `GET /announcements/visible` | 当前账号可见公告列表 |
| `POST /announcements/visible/:id/confirm` | 确认公告已读 |
| `GET/POST/PATCH/DELETE /announcements/admin/...` | 公告后台管理 |
| `POST /announcements/admin/:id/publish` | 立即发布公告 |
| `POST /announcements/admin/:id/archive` | 归档公告 |
