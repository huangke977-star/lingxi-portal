## 一、功能入口

| 功能 | 入口 | 权限 |
| --- | --- | --- |
| 订阅动态 | 发现 -> 订阅 | 登录用户 |
| 我的合集 | 发现 -> 合集 | 登录用户 |
| 专题列表 | 发现 -> 专题 | 游客和登录用户，内容按权限过滤 |
| 专题管理 | 专题 -> 管理专题，或 `/admin/topics` | 管理员、超级管理员 |
| 主页展示设置 | 个人中心 -> 主页展示 | 当前账号 |
| 用户公开主页 | 用户头像、昵称或 `/users/:username` | 游客和登录用户 |

## 二、订阅动态

订阅动态从现有作者订阅关系生成，不复制文章正文，也不增加新的推荐服务。

- `最新`：按发布时间和文章 ID 倒序。
- `未读`：未读文章优先，同一组内仍按发布时间倒序。
- `热度`：依次按评论、收藏、点赞、阅读和发布时间排序。
- 单条已读记录存入 `subscription_feed_reads`，因此换浏览器或设备后仍保持一致。
- `全部已读` 使用批量写入和唯一键去重，不会重复生成记录。
- 作者级推送开关只控制“新文章通知”，关闭后仍保留订阅关系和订阅动态。
- 文章发布通知只发送给启用了 `notify_new_articles` 的订阅者。

## 三、文章合集

每个用户只能管理自己的合集，合集删除不会删除文章。

- 支持创建、修改、删除和合集内文章排序。
- 只能加入当前账号自己的有效文章。
- 可见范围包括：公开、登录可见、仅自己。
- 排序接口要求提交当前合集的完整文章 ID 集合；缺少、重复或混入其他文章都会拒绝。
- 公开合集可以通过 `/collections/:id` 分享，登录可见和私有合集会在 API 层继续校验访问者。

## 四、管理员专题

专题用于跨作者组织文章，由管理员和超级管理员共同维护。

- 支持标题、路径标识、封面路径或网址、说明、状态和排序。
- 可见范围包括：公开、登录可见、指定角色。
- 指定角色专题必须至少选择一个有效角色。
- 停用专题不会出现在普通专题列表中。
- 专题内文章支持加入、移除和完整排序。
- 专题删除不会删除文章。

普通文章卡片和阅读页只返回当前访问者有权打开的合集与专题标签：游客只看公开归属，登录用户可看登录可见归属，指定角色专题按角色过滤，私有合集只对所有者和超级管理员显示。

## 五、个人主页

用户可以在个人中心控制以下公开字段：

- 个人介绍。
- 加入时间。
- 内容与访问统计。
- 已订阅数量。
- 代表内容。

代表内容包括一篇已发布文章和一个自己的合集。关闭“代表内容”后，公开主页不返回也不显示相应内容。

公开主页可以展示：

- 代表文章与代表合集。
- 当前访问者可见的文章合集。
- 公开文章、获赞、阅读、订阅者、已订阅和主页访问统计。

当前用户查看自己的主页时仍可看到自己的完整信息，方便确认设置；其他访问者严格按隐私开关接收字段。

## 六、访问统计与隐私

主页访问记录按“访问者 + 日期”去重：

- 登录访问者使用用户 ID 生成 SHA-256 哈希。
- 匿名访问者使用 IP 与 User-Agent 生成 SHA-256 哈希。
- 数据库只保存 64 位哈希和日期，不保存原始 IP 或 User-Agent。
- 用户关闭统计公开后，API 不返回访问量，也不会额外查询其他公开统计。
- 用户访问自己的主页不计入访问量。

该统计用于提供轻量级访问趋势，不用于精确设备识别或跨站追踪。

## 七、主要 API

| 路径 | 作用 |
| --- | --- |
| `GET /discovery/feed` | 订阅动态、未读数和排序 |
| `POST /discovery/feed/:articleId/read` | 单条已读 |
| `POST /discovery/feed/read-all` | 全部已读 |
| `GET/PATCH /discovery/subscriptions/...` | 作者推送设置 |
| `GET/POST/PATCH/DELETE /discovery/collections/...` | 合集管理与排序 |
| `GET /discovery/topics...` | 公开或当前用户可见专题 |
| `GET/POST/PATCH/DELETE /discovery/admin/topics...` | 管理员专题管理 |
| `GET/PATCH /discovery/profile/settings` | 主页隐私和代表内容设置 |
| `GET /discovery/profiles/.../:username` | 主页代表内容、合集和访问统计 |
