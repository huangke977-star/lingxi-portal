# HLOVET 媒体备份与恢复

- 文档状态：第一阶段实施文档
- 适用范围：背景图片、站点资源、Android 安装包、用户头像、文章图片、聊天附件
- 对应英文文档：`docs/media-backup-and-recovery.en.md`

## 一、设计目标

媒体备份只处理数据库已经引用且磁盘中真实存在的持久化文件。数据库有记录但文件缺失、磁盘有文件但数据库无记录、临时上传和回收站文件均由存储修复流程处理，不会混入正常备份。

备份任务默认单并发、逐个文件读取和上传，避免在低内存 VPS 上同时占用大量内存、磁盘带宽和网络带宽。网站登录、文章和聊天接口不依赖备份任务完成。

## 二、文件生命周期

1. 存储扫描核对数据库引用和磁盘文件。
2. 六类有效文件同步到媒体备份目录表。
3. 备份任务根据文件大小和修改时间决定是否复用已有哈希。
4. 需要计算哈希时按流读取文件并生成 SHA-256。
5. 远端已经存在相同内容时记录为复用，否则加密后上传。
6. 每个文件、提供商和任务都生成备份清单记录。
7. 恢复时先下载到临时目录，解密并校验大小和 SHA-256。
8. 校验通过后才原子替换目标文件，并记录处理结果。

## 三、增量与排除规则

- 文件大小和修改时间未变化时复用已有哈希。
- 同一远端提供商已有成功清单且哈希一致时，不重复上传。
- 不同路径但内容完全一致的文件可以复用同一远端对象。
- `.tmp`、`.trash`、未完成上传和已经不在最近扫描结果中的目录记录不会进入任务。
- 文件在哈希或上传过程中被删除、替换或修改时，本次记录为跳过或失败，不写入错误哈希。
- 备份任务默认并发数为 1；不得通过部署环境擅自提高到会影响生产接口的数值。

## 四、远端配置

媒体备份复用“系统运行概览”中的阿里云 OSS / Cloudflare R2 配置和 `BACKUP_ENCRYPTION_KEY`。访问凭据在数据库中加密保存，API 不返回明文。

启用提供商前必须完成连接测试。至少启用一种提供商后，媒体任务才会执行真实远端上传；未启用提供商时可以查看目录覆盖率，但手动或定时远端任务不会伪装成成功。

对象默认保持私有。远端文件使用 AES-256-GCM 加密，恢复时必须使用与备份时一致的 `BACKUP_ENCRYPTION_KEY`。

## 五、调度、保留与重试

- 手动任务由超级管理员在系统运行概览中启动。
- 定时任务使用已保存的时区与执行时间；服务重启后会补跑当天未完成的任务。
- 同一时间只允许一个媒体备份任务运行。
- 数据库备份与媒体备份共用一个 I/O 通道；发生冲突时，定时任务不会记为失败，而会在下一轮调度重试。
- 单文件上传失败采用有限次数重试和递增等待，不进行无限循环。
- 本地任务和清单按保留策略清理；被仍在使用的远端对象不能因旧任务清理而误删。
- 每次任务记录触发方式、提供商、总文件数、上传/复用/跳过/失败数量、字节数、时间和错误摘要。

## 六、缺失文件处理

存储管理中的缺失文件支持三种处理方式：

1. 远端恢复：选择可用备份，下载到临时位置并完成哈希和大小校验后替换。
2. 重新上传：新文件先写入临时位置，校验成功后替换到原路径。
3. 确认无法恢复：保留原业务记录，只关闭当前异常并记录确认结果。

重新扫描会重新核对实际状态。如果业务记录仍然引用已确认无法恢复的文件，扫描仍会留下已处理记录和缺失统计，但不会把同一文件重新放入待处理列表；后续重新上传或远端恢复成功后，该确认状态会被新的处理记录替代。

## 七、轻量运行观测

系统只记录有限窗口内的慢接口、API 错误以及内存和磁盘采样，不引入新的常驻监控服务。

- 慢接口记录方法、标准化路径、状态码、耗时和发生时间，不记录密码、令牌或请求正文。
- 最近错误记录状态码、标准化路径和错误摘要，数量受上限和过期时间控制。
- 内存和磁盘趋势按固定周期采样，采用有界历史数据。
- 系统运行概览展示媒体覆盖率、未备份数、最近成功任务、失败数和存储异常数。

## 八、通知规则

以下情况通过现有“系统”通知频道发送给超级管理员：

- 媒体备份任务失败或部分失败。
- 磁盘使用率达到存储管理阈值。
- 最新扫描的缺失文件数量发生变化。

通知有冷却和去重机制，避免定时扫描或重复失败持续刷屏。通知只包含定位信息和错误摘要，不包含云端凭据。

## 九、恢复演练

生产恢复演练只使用可替换的测试文件，不直接拿唯一业务文件试验。

1. 确认至少一个远端提供商连接测试成功并已启用。
2. 执行存储扫描并确认测试文件进入备份目录。
3. 执行媒体备份，确认任务完成且对应清单为“已上传”或“已复用”。
4. 记录测试文件的 SHA-256 和大小。
5. 将测试文件移动到独立安全目录，制造可恢复的缺失状态。
6. 在存储管理中对该缺失项执行远端恢复。
7. 再次计算 SHA-256 和大小，必须与步骤 4 完全一致。
8. 执行一次完整存储扫描，确认缺失项消失。

如果远端凭据尚未配置，只能完成目录、哈希、清单和本地临时恢复验证，不能把它记为真实远端恢复演练通过。

## 十、故障处理

- 任务长时间运行：先查看当前处理文件和最近更新时间，不要直接重启 MySQL、Redis、Caddy 或 TURN。
- 远端连接失败：使用提供商连接测试核对权限、Bucket、Endpoint 和服务器出网。
- 哈希不一致：保留临时文件用于诊断，禁止覆盖原目标文件。
- 磁盘压力过高：暂停自动媒体备份，处理回收站和孤立文件后再继续。
- 加密密钥丢失：已有远端加密对象无法恢复，应将密钥作为服务器机密单独备份。
