# HLOVET 六阶段产品与技术路线图

- 文档状态：生效中
- 建立日期：2026-08-04
- 最近更新：2026-08-05
- 当前阶段：第一阶段进行中
- 对应英文文档：`docs/six-phase-roadmap.en.md`

## 一、文档用途

本文档是 HLOVET 后续开发的长期执行依据。后续开始新任务或新对话时，应先读取本文档，从第一个未完成的任务编号继续，并在开发、测试和部署后同步更新状态与完成记录。

状态定义：

- `未开始`：尚未进入开发。
- `进行中`：已经开始设计或实现。
- `已完成`：代码、测试、文档和生产验证均已完成。
- `阻塞`：缺少外部配置、用户决策或第三方服务。

## 二、总体原则

1. 六个阶段属于同一份长期计划，但必须分阶段开发和部署。
2. 每个阶段都必须可以独立上线和回滚，不积累到最后一次性发布。
3. 数据库迁移优先使用增量、兼容性变更，避免直接破坏现有数据。
4. 未完成或未验收的功能通过权限或功能开关隐藏。
5. 继续复用 MySQL、Redis、Socket.IO、现有消息系统和现有 OSS/R2 配置。
6. 不引入 Elasticsearch、Prometheus、Grafana、ClickHouse 等高资源常驻服务。
7. 后台任务限制并发和磁盘 I/O，避免再次造成服务器卡顿。
8. 所有新增文档同时提供中文和英文版本。
9. 每个阶段完成后更新本文档、提交编号、部署时间和生产验证结果。

## 五、第一阶段：可靠性基础

目标：让数据库记录和实际文件都具备可核查、可备份、可恢复的完整生命周期，并提供不依赖大型监控组件的基础运行观测能力。

### 开发任务

| 编号 | 内容 | 状态 |
| --- | --- | --- |
| P1-01 | 建立媒体备份任务、备份文件和备份清单数据模型 | 已完成 |
| P1-02 | 覆盖背景、站点资源、APK、头像、文章图片和聊天附件六类文件 | 已完成 |
| P1-03 | 根据文件哈希、大小和备份清单执行增量备份 | 未开始 |
| P1-04 | 复用现有 OSS/R2 加密配置，支持启用、停用和连接测试 | 未开始 |
| P1-05 | 排除 `.tmp`、`.trash` 和未完成上传，默认并发限制为 1 | 未开始 |
| P1-06 | 支持定时备份、保留策略、失败重试和任务日志 | 未开始 |
| P1-07 | 支持单文件恢复，先恢复到临时目录，校验后原子替换 | 未开始 |
| P1-08 | 缺失文件增加“远端恢复、重新上传、确认无法恢复”处理流程 | 未开始 |
| P1-09 | 增加慢接口、最近 API 错误、内存和磁盘趋势的轻量统计 | 未开始 |
| P1-10 | 在系统概述展示备份覆盖率、最近成功时间和异常数量 | 未开始 |
| P1-11 | 备份失败、磁盘超限和缺失文件变化时通知超级管理员 | 未开始 |
| P1-12 | 完成中英文文档、自动化测试、部署与生产恢复演练 | 未开始 |

### 验收标准

1. 六类持久化文件都能生成备份清单。
2. 未变化文件不会在每次任务中重复上传。
3. 备份执行期间网站登录、文章和聊天接口保持可用。
4. 能从远端恢复一个测试文件，并通过哈希和大小校验。
5. 缺失文件可以重新上传或从备份恢复，处理状态会被记录。
6. 系统概述可以看到最近备份、未备份数量和任务失败状态。

### 暂不包含

- 整机镜像备份。
- Docker 卷快照。
- 任意宿主机目录备份。
- 引入新的常驻备份服务。

## 六、第二阶段：账号安全

目标：在开放注册的前提下补齐账号找回、机器人防护和登录风险感知。

### 开发任务

| 编号 | 内容 | 状态 |
| --- | --- | --- |
| P2-01 | 增加 SMTP 管理配置、连接测试和凭据加密保存 | 未开始 |
| P2-02 | 注册邮箱验证码与验证码频率限制 | 未开始 |
| P2-03 | 忘记密码、重置令牌和全部旧会话失效 | 未开始 |
| P2-04 | 注册、登录失败过多和密码找回接入 Turnstile | 未开始 |
| P2-05 | 识别新设备、陌生 IP 和异常登录频率 | 未开始 |
| P2-06 | 通过站内消息和邮件发送登录风险提醒 | 未开始 |
| P2-07 | 在个人中心增加账号安全日志和最近安全事件 | 未开始 |
| P2-08 | 增加登录提醒、邮件提醒和新设备提醒开关 | 未开始 |
| P2-09 | 管理后台提供验证码、邮件任务和风险事件查询 | 未开始 |
| P2-10 | 完成限流、令牌失效、安全测试和中英文文档 | 未开始 |

### 验收标准

1. 用户能够通过已验证邮箱重置密码。
2. 重置密码后旧 Refresh Token 全部失效。
3. 机器人注册和高频验证码请求受到限制。
4. 新设备登录会生成可查询的安全事件和提醒。
5. 邮件服务不可用时不会阻塞普通登录，并能在后台看到失败原因。

### 暂不包含

- 强制所有用户绑定邮箱。
- 短信验证码。
- 第三方账号登录。

### 验收标准

1. 文章编辑过程中无需手动点击即可保存草稿。
2. 页面关闭或网络中断后可以恢复最近内容。
3. 用户可以查看和恢复历史版本。
4. 搜索结果不会泄露无权访问的文章、服务器入口或私有数据。
5. 搜索结果支持分页，并在移动端正常显示。

### 暂不包含

- Elasticsearch 或独立搜索集群。
- 多人同时协作编辑同一篇文章。
- Office 文档在线编辑。

- 付费内容和会员订阅。
- 完全自由的页面搭建器。

## 十一、每个阶段的统一完成标准

每个阶段只有满足以下条件后才能标记为“已完成”：

1. Prisma Schema 与迁移通过生成和校验。
2. API 测试、Lint 和生产构建通过。
3. Web Lint 和生产构建通过。
4. Docker Compose 生产配置校验通过。
5. 桌面端和移动端完成 Playwright 关键流程检查。
6. 权限、登录过期和错误提示行为完成验证。
7. 中英文文档同步更新。
8. 代码已提交并推送，GitHub Actions 镜像构建成功。
9. 生产迁移和部署成功，MySQL、Redis、Caddy、TURN 不被无关重启。
10. 生产健康接口、日志、内存和核心流程验证通过。
11. 本文档对应任务状态和完成记录已经更新。

## 十三、后续任务恢复规则

以后继续这份计划时，执行顺序固定为：

1. 读取本路线图和对应英文文档。
2. 检查仓库当前代码、生产状态和未提交修改。
3. 找到当前阶段中编号最靠前的“未开始”或“进行中”任务。
4. 核对前置配置是否齐全。
5. 完成实现、测试、推送和部署。
6. 更新任务状态、阶段总览和完成记录。

不得仅根据旧对话记忆判断完成情况，必须以仓库代码、数据库迁移、生产验证和本文档记录为准。
